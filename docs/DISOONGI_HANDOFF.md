## 1. 먼저 읽고 판단할 것

디숭이는 기획안이나 공개 대기 시안이 아니라 **디어한의원 홈페이지에 일반 공개된 AI 안내 서비스**다. 다음 세션은 공개 준비를 처음부터 다시 시작하지 않는다. 사용자가 실제로 써 보고 주는 피드백을 받아 이미 합의한 방향을 보존하며 수정하는 단계다.

필수 순서는 저장소 `AGENTS.md` → `CLAUDE.md` → `HANDOFF.md` → `COLLABORATOR_BRIEF.md`, 그리고 디숭이 작업이면 이 문서다. 날짜별 과거 기록에 있는 ‘공개 금지’, ‘테스트 전용’, ‘미해결’ 표현은 당시 상태다. 최신 합의와 실코드·실서버를 대조하지 않고 과거 상태로 되돌리지 않는다. 이 문서 역시 작성 시점의 기록이므로 이후 커밋과 사용자 지시가 우선한다.

대표·최종 의사결정권자는 김민지 대표원장(부끄님), 기획·브랜드·카피 협업자는 박성호(삥이)다. 삥이를 원장이나 병원 대표로 쓰지 않는다. 사용자는 개발 조작에는 단계 안내가 필요하지만 마케팅·브랜드 기획의 초보가 아니다. 질문·검토 요청을 구현 승인으로 해석하지 않으며, 수정 승인이 있으면 요청 범위의 검수와 실제 반영까지 완료한다.

## 2. 무엇을 만들려 했는가

목표는 홈페이지 방문자가 ‘누구에게 무엇을 물어야 할지’ 망설이는 순간에 디숭이가 편하게 말을 걸 수 있는 입구가 되는 것이다. 진료 분야와 내원·예약 방법을 알아보고, 필요한 순간 대표원장 진료로 연결한다. 단순 전화번호 팝업이나 키워드 FAQ가 아니라 실제 대화 맥락을 읽는 안내 캐릭터다.

삥이는 광고 유입의 이탈을 줄이기 위해 캐릭터·말투·위치·모션·예약 동선까지 직접 시험했다. 기술적으로 안전하다는 이유만으로 사용자가 대화하기 싫어지는 거대한 경고 화면이나 매번 같은 훈계 문구로 바꾸면 의도를 훼손한다. 그렇다고 진단·처방·치료 보장이나 실제 긴급 징후 무시를 허용한 것은 아니다. 안전선과 친근한 이용 경험을 함께 유지한다.

현재 기능을 새로 발명하거나 전면 개편할 필요는 없다. 이미 승인받은 자산·문구·흐름을 기준으로 구체적인 문제를 재현해 고친다.

## 4. 구조와 데이터 흐름

```text
홈페이지 공통 로더(js/main.js) 또는 독립 페이지 연결
  → js/dear-ai-widget.js: Shadow DOM 실행 버튼·말풍선·패널
  → iframe: preview/dear-ai.html
  → js/dear-ai-consent.js: 안내·동의 등록·철회
  → js/dear-ai.js: 대화 표시·문맥·전송·예약 버튼
  → Cloudflare Worker: 출처/요청/동의/제한 검사
  → ChatBudget Durable Object: 동의 증표·일/월 요청 합계
  → Anthropic Messages API: 문맥 기반 답변과 행동 분류
  → 클라이언트: 평문 답변 + 필요한 경우 고정된 예약 CTA
```

AI의 `answer_visitor` 출력은 `reply`, `action`, `booking_route`다. 행동은 `continue`, `offer_booking`, `urgent_help`이며 클라이언트가 해당 행동을 실제 화면으로 표시한다. 임의 URL이나 버튼 HTML을 모델 답변으로 받아 실행하는 구조가 아니다. 답변 문구만 보는 검수와 실제 action/route 검수를 구분한다.

대화는 최근 최대 14개 메시지를 전송한다. 임베드 화면은 해당 탭의 임시 저장을 사용해 페이지 간 이어가며 마지막 저장 후 30분을 넘은 기록은 다음 채팅 로드 때 삭제한다. 독립 화면은 페이지 메모리 기반이다. 서버가 모든 대화를 장기 보관해 학습하는 서비스가 아니다. 홈페이지 칼럼을 변경했다고 프롬프트의 진료 지식까지 자동 갱신됐다고 주장하지 않는다. 진료시간·공식 사실 변경 시 서버 지식과 화면의 동시 반영 여부를 확인한다.

## 5. 말투·일반 대화의 합의

- 따뜻한 해요체, 카카오톡으로 편하게 안내하는 정도의 자연스러움이 기본이다. 공문체, 과도한 유행어, 매번 같은 웃는 얼굴을 피한다.
- 짧은 질문에는 짧게 답하고, 자세한 고민에는 필요한 만큼 답한다. 매번 질문으로 끝내거나 예약을 반복 권유하지 않는다.
- 오타·반말·사투리·밈·욕설은 뜻과 감정을 먼저 읽는다. 표현을 교정하거나 모욕당한 척 훈계하지 않는다. 예약 질문이 명확하면 예약을 도와준다.
- 성적 장난에는 선정적인 대화를 이어가는 대신 안내 역할로 자연스럽게 돌아온다. 사용자가 실제로 시험해 본 응대는 만족한 상태다. 욕설 횟수에 따른 제재·대화 강제 종료 기능을 추가하기로 합의한 것은 아니다.
- 이모지는 문맥에 맞게 소량 사용하고 진지하거나 긴급한 상황에서는 장식하지 않는다. `:)`, `^~^` 같은 이모티콘을 문자열 정리 과정에서 훼손하지 않는다.
- 별표 강조가 `**네이버 예약**`처럼 화면에 노출됐던 문제가 있었다. 현재 평문 지침과 남은 별표 강조 정리를 유지한다. 마크다운을 무작정 렌더링하도록 바꾸지 않는다.
- 모르는 가격·통역·직원 외국어 가능 여부·예약 확정 여부를 지어내지 않는다. 환자에게 직원 메시지 전송이나 예약 완료를 했다고 말하지 않는다.

## 6. 증상·진단 질문과 응급 안내: 가장 중요한 수정 맥락

문제가 된 실제 흐름은 ‘열이 너무 나요 감기인가요?’라는 질문에 AI가 여러 증상 설명과 가정형 응급 징후, 119·응급실을 길게 덧붙인 것이었다. 삥이가 반대한 것은 모든 증상에서 최악을 상정하여 한의원·1차 진료를 배제하는 응대다. 실제 긴급 상황 안내를 전부 삭제하자는 합의가 아니다.

현재 기준:

1. 단순 증상 호소: 먼저 공감한다. 시작 시점·부위 등 필요한 맥락 한두 개만 짧게 묻는다.
2. 진단 요청: 공감 → AI가 진단을 대신할 수 없다는 짧은 설명 → 김민지 대표원장이 증상과 경과를 살필 수 있다는 안내 → `offer_booking`으로 예약 버튼을 제공한다.
3. 실제 구체적인 긴급 문맥: `urgent_help`와 간결한 긴급 안내를 유지한다. 사용자가 ‘응급’이라는 단어를 말해야만 동작하는 것은 아니다.
4. 부정한 증상·과거에 끝난 증상·단순 가정을 현재 응급 증상으로 오인하지 않는다. 모든 답변에서 ‘혹시 숨이 차거나 의식이 흐려지면’ 같은 조건문을 덧붙이지 않는다.

‘대표원장님이 잘 도와주실 것’이라는 브랜드 신뢰는 직접 진찰·상담 안내로 표현한다. 모든 질환 해결·치료 성공을 약속하는 문장으로 바꾸지 않는다. 응급 문구를 출력 후 정규식으로 지워 실제 응급까지 숨기는 방식도 사용하지 않는다.

이전 실제 유료 표본 5개는 열/복통 진단 질문 → 예약, 단순 복통/두통 → 맥락 질문, 갑작스러운 심한 흉통+호흡곤란 → 긴급 안내를 확인했다. 프롬프트 변경 후에는 같은 문장만 통과시키지 말고 부정·과거·연속 대화도 필요한 범위에서 검수한다. 현재 자동 시험의 일반 증상 정규식 검사는 회귀 신호이며 모든 의료 안전을 판정하는 규칙은 아니다.

## 7. 예약 분류와 다국어

| 상황 | route | 실제 선택지 |
| --- | --- | --- |
| 국내 일반 예약 | `domestic` | 네이버 예약·톡톡·전화 |
| 한국인이 네이버를 못 쓰거나 원치 않음 | `domestic_alternative` | 인스타그램 문의·전화 |
| 외국인 진료 안내 | `international` | 외국인 일정·예약 안내 페이지·인스타그램 문의·전화 |

외국어 페이지의 기본 경로는 international이지만 언어만으로 국적을 단정하지 않는다. 사용자가 밝힌 상황을 우선한다. 한국인이 네이버 계정이 없다는 이유로 외국인 전용 페이지에 보내면 안 된다.

외국인 예약 페이지는 자체 예약 접수 폼이 아니라 일정 확인·전화 안내 페이지다. 인스타그램은 공식 계정을 열어 사용자가 DM을 보내는 방식이다. AI가 DM을 발송하거나 직원에게 대화 기록을 자동 전송하지 않는다.

화면 언어는 한국어·영어·일본어·중국어를 지원한다. 대화는 방문자 언어에 자연스럽게 맞추되, 안내 링크·동의·개인정보처리방침도 해당 언어와 일치해야 한다. UI 번역만 바꾸고 나머지 세 언어를 방치하지 않는다.

## 8. 캐릭터 고증: 교체하지 말아야 할 것

디숭이는 ‘비슷한 새 사슴 캐릭터’가 아니라 부끄님이 만든 디어한의원의 캐릭터다. 이마의 D는 DEAR 정체성의 일부다. 원본의 실루엣·얼굴·비율·색감·질감·표식의 방향과 조각 형태를 보존한다.

처음 원형 프로필을 실행 버튼에 넣었을 때 너무 작고 얼굴만 확대돼 보인다는 피드백이 있었다. 사용자는 머리띠를 쓴 캐릭터만 누끼 상태로 단독 표시되기를 원했다. 후속 시안 중 팔다리가 길어진 안은 거절했고 **첫 시안의 짧고 통통한 비율**을 선택했다. D를 새로 생성해 부정확하게 만드는 것도 거절했다.

현재 바깥 실행 버튼은 `assets/images/disoongi-launcher-v1.webp`, 보존본은 같은 이름의 PNG다. 채팅 안 프로필 `assets/images/disoongi-profile.png`와는 별개다. 바깥 버튼만 바꾼 일을 채팅 프로필까지 교체한 것으로 혼동하지 않는다.

현재 자산은 머리띠·손 인사·투명 배경을 갖고, 원본 참고 이미지의 이마 표식을 반영했다. `tools/prepare-disoongi-launcher.py`는 당시 자산 준비 도구다. 입력 원본이 새 PC에 없으면 임의로 재생성하지 말고 기존 배포 자산을 쓰거나 원본 제공을 요청한다. 자산 수정은 원본 대조와 사용자 확인 후 적용한다.

2026-09-07 채팅 프로필이 작고 잘 보이지 않는다는 피드백을 반영했다. 원본 PNG(1006×1440)는 보존하고 상단 원형을 58px, 답변 옆 원형을 42px로 확대했다. 처음에는 이미지 배율 140%와 위치 조정으로 얼굴·이마 표식을 중심에 뒀다. 후속 확인에서 일반 1배 화면의 윤곽선 끊김이 남아, 원본 얼굴 영역(x121/y318, 719px 정사각형)을 Lanczos3로 정밀 축소한 disoongi-face-58 및 disoongi-face-42의 1x/2x/3x PNG로 교체했다. srcset으로 화면 밀도에 맞는 파일을 선택하며 CSS 확대·translate는 제거했다. 상단·첫 인사·추가 답변·로딩에 동일하게 적용한다. 새 캐릭터 생성이나 원본 색·질감 변경은 하지 않았다.

## 9. 위젯·모션·본문 방해 최소화

- 위젯은 메인만이 아니라 공통 페이지와 독립 외국인 예약 페이지에 연결되어 있다. `preview/` 안에서는 바깥 위젯을 다시 만들지 않는다.
- 실행 버튼은 PC 144×214px, 768px 이하 100×149px의 전신 이미지다. 원형 배경·강제 얼굴 크롭을 복원하지 않는다.
- 인사 말풍선은 Pretendard. 메인은 ‘궁금한 거 있어요? / 제가 도와드릴게요 :)’ 두 줄, 서브는 여기에 이동·접기 안내를 더한다.
- 최초 약 1.8초 뒤 표시, 6초 노출, 12초 휴식의 반복이다. ‘같은 탭 최초 한 번만’은 사용자 피드백으로 폐기한 방식이다.
- 채팅 열림·접힘·드래그·숨겨진 브라우저 탭 등의 상태를 고려한다. hover/focus와 자동 표시가 서로 충돌하지 않는지 확인한다.
- 패널은 열기·닫기에 약 220ms 전환을 사용하고 움직임 최소화 설정에서는 모션을 줄인다. 닫기 직후 패널이 클릭을 가로채지 않아야 한다.
- 포인터 드래그와 Alt+방향키로 이동한다. 6px 미만은 클릭으로 처리하며 드래그 후 채팅이 실수로 열리지 않게 한다. 화면 밖으로 나가지 않게 제한한다.
- − 버튼으로 작은 탭 형태로 접고 다시 펼친다. 위치·접힘 상태는 같은 탭의 페이지 이동에서 이어진다.
- 현재는 사용자가 옮기거나 접어 방해를 줄이는 구조다. 모든 본문 요소를 자동으로 감지해 피하는 기능이 있는 것처럼 설명하지 않는다.

채팅 배경은 기존 원내 공간 사진 `care-main-space.jpg`와 옅은 크림 덮개다. 가독성과 공간감이 함께 보이는 것이 의도다. 동의 화면은 불투명 전면 가림 대신 작은 하단 카드이며 뒤의 프로필·첫 인사를 어느 정도 볼 수 있다. 배경이 보이더라도 동의 전 채팅을 조작할 수 있게 만든 것은 아니다.

## 10. 동의 UX와 개인정보처리방침

최종 구현은 **기본 미체크**, 사용자가 누르는 전체 동의, 항목별 선택·해제다. 사용자가 사전 체크를 여러 차례 물었지만 실제 합의·배포 상태를 사전 체크로 기록하면 안 된다. 연령 확인과 개인정보·건강정보·국외 이전 항목을 유지한다.

첫 화면은 ‘안녕하세요, 디숭이예요’ 같은 친근한 인사와 질문 초대가 먼저다. 불필요하게 겁을 주는 반복 경고나 개발 세부 사항은 줄인다. 미동의 상태에도 전화·외부 예약 안내를 제공한다. 카드가 작아도 작은 화면에서 모든 항목과 시작 버튼에 접근할 수 있어야 한다.

동의 UI는 `js/dear-ai-consent.js`다. `js/dear-ai.js`만 수정해서 동의 전체를 고쳤다고 생각하지 않는다. 서버의 동의 버전·각 항목 검사·증표 만료·철회와 함께 검증해야 한다. UI 체크만 있고 서버가 무동의 요청을 받아들이는 상태로 바꾸지 않는다.

브라우저 삭제와 공급자 데이터 삭제, 서비스 자체 로그와 공급자 운영 로그를 구분한다. 임시 동의 번호·안내 버전·접수/만료 시각은 대화와 분리 보관하며 30분 만료·철회/정리 기능이 있다. 이것을 장기 법적 증빙 시스템이라고 부르지 않는다.

9월 6일 네 언어 방침의 AI 구역을 ‘대화 기록 → 업체/보관기간 표 → 국외 전송 → 동의·철회’로 정리했다. `sessionStorage`·해시 테이블·테스트 코드 같은 내부 설명과 중복을 덜고 중요 보관기간·예외·공식 링크는 남겼다. 시행일·이전 방침은 하단 유지, 진료·분석 등 다른 조항은 임의 개정하지 않았다. 문구 가독성만 바뀌어 동의 버전은 유지했다.

개인정보 문구를 수정할 때 실제 코드와 공급자 최신 정책을 대조한다. 단순 편집을 새 법적 적정성 보증으로 보고하지 않는다. 공급자 국외 처리 범위에 확인이 남았다는 이유만으로 불법·신고·자동 운영 중단을 단정하지도 않는다. 공급자에게 해명성 문의를 발송하거나 이메일 회신을 필수 공개 조건으로 삼는 것에 사용자는 반대했다. 외부 발송·새 계약·운영 중단은 별도 승인 없이 실행하지 않는다.

## 11. 비용과 보호 장치

현재 설정은 IP당 12회/60초, 사이트 전체 200회/일·2000회/월, 최대 출력 500토큰이다. Worker 상위 요청 제한 시간은 25초, 화면은 30초다. 요청 크기·출처·동의·예산 검사도 있으므로 관련 수정 시 실제 검사를 확인한다.

요청 횟수는 고정 월 요금이 아니다. 대화 길이와 입력·출력 토큰, 재전송하는 최근 문맥에 따라 비용이 달라진다. 사용자가 ‘커피값’이라는 예상과 실제 차감 차이에 민감했으므로 무조건 저렴하다고 약속하지 않는다. 잔액·자동 충전·계정 지출 한도는 Console의 실제 설정을 확인해야 하며 과거 스크린샷을 현재 잔액으로 쓰지 않는다.

모든 테스트를 유료 API로 실행하지 않는다. 정적·모의 검사가 먼저이며 프롬프트/실제 연결 확인이 필요한 경우에만 제한된 가상 문장으로 시험한다. 사용자 승인 없이 모델을 저가 모델로 바꾸거나 제한을 늘리지 않는다. 대화 원문을 비용 분석 목적으로 분석 도구에 새로 저장하는 것도 범위 확장이다.

## 12. 과거 403 오류: 다시 같은 우회를 반복하지 않기

Console Playground는 같은 모델에서 성공했고, 사용자가 같은 키를 PC의 숨김 입력 시험으로 호출했을 때 `HTTP: 200 / RESULT: SUCCESS`를 확인했다. Worker에서는 최소 인사 요청도 Anthropic 403 `Request not allowed`였다. 키 형식 검사는 통과했고 당시 경로 코드에는 HKG가 관측됐다.

공식 Placement Hints의 `placement.region: aws:ap-northeast-2`를 적용한 뒤 같은 Worker의 실제 답변이 성공했다. 키·모델·DNS·결제 플랜을 바꾸지 않고 해결했다. 그러므로 비슷한 문제가 재발하면 먼저 실패 상태·Worker 설정·현재 경로/공급자 상태를 구분한다. 또 결제하라거나 키를 계속 새로 만들라고 하지 않는다.

이 기록은 경로 설정 변경과 성공의 연관성을 보여줄 뿐 공급자의 내부 차단 규칙을 확정한 것이 아니다. Placement는 지정 리전에 지연시간상 가까운 실행 위치를 고르는 설정이며 서울 고정·한국 내 모든 처리·국내 데이터 보관 보장이 아니다.

## 14. 검증 방법과 증거 수준

프로젝트 루트에서 기본 검사:

```powershell
node tools/test-dear-ai.mjs
node tools/test-dear-ai-public.mjs
node tools/test-seo-surfaces.mjs
git diff --check
```

동의·예산 저장 로직 변경 시 `node tools/test-dear-ai-budget-runtime.mjs`도 실행한다. Worker 의존성 설치와 검사 명령은 `worker/dear-ai/package.json`을 확인한다. 새 PC에는 설치된 의존성·Cloudflare 인증이 없을 수 있다. 기능 코드를 읽는 것과 운영 권한을 가진 것은 다르다.

공개 실제 모델 검사:

```powershell
node tools/smoke-dear-ai-release.mjs --public
node tools/smoke-dear-ai-release.mjs --public --symptoms
```

첫 명령은 국내/네이버 미사용/영·일·중/긴급 6종, 둘째는 증상 5종이며 각각 유료 API 호출이 발생한다. 공개 모드의 스크립트는 테스트 비밀키를 만들지 않는다. `--public`을 빼면 과거 비공개 QA 절차로 달라지고 현재 health 상태와 맞지 않아 중단되므로 습관적으로 생략하지 않는다. 실제 대화 뒤 철회 및 같은 증표 재사용 428까지 검사한다.

UI를 수정하면 1440px PC, 768px 태블릿, 390px 모바일에서 아래를 확인한다.

- 메인/칼럼/서비스/독립 외국인 페이지의 진입과 중복 위젯 여부.
- 반복 말풍선, 긴 외국어, 열기·닫기·Escape, 드래그 후 오클릭, 접기·복원.
- 좁은 화면에서 항목·동의 버튼 접근, 미체크 상태, 전체 선택 후 개별 해제.
- 동의 전 전송 차단, 만료·철회 이후 전송 차단, 기존 대화/진행 중 응답 정리.
- 국내/외국인 CTA의 실제 URL, 외부 예약 완료로 오인시키지 않는 문구.
- 가로 넘침·본문/퀵메뉴 간섭·키보드 초점·reduced-motion.

정적 검사 통과, 브라우저 실제 동작, 배포 성공, 유료 API 실제 응답은 서로 다른 증거다. 하나로 나머지를 보증하지 않는다. 예전 79페이지·26칼럼 검증 숫자도 후속 발행 뒤에는 현재 sitemap에서 다시 계산한다.

## 15. 두 배포 경로와 장애 대응

사이트는 관련 파일만 커밋해 `master`로 push하면 Pages가 배포한다. 프롬프트나 Worker 설정은 **push만으로 적용되지 않는다**. 해당 Worker 프로젝트의 검사·별도 배포와 운영 결과 확인이 필요하다. 사용 가능한 Wrangler 도구/스킬 지침을 읽고 정확한 계정·Worker를 확인한 뒤 실행한다. 이번 문서 작성에서는 Worker를 배포하지 않는다.

배포 전 diff를 확인하고 사용자 소유 변경을 섞지 않는다. `git add .`, 강제 push, hard reset으로 정리하지 않는다. 키는 Worker Secret에 두며 공개 Git·명령 인자·로그·스크린샷에 값이 나오지 않게 한다. 다른 PC라고 새 키를 요구하거나 기존 Secret 값을 추출하지 않는다.

문제 제보 시 순서:

1. 화면 URL·언어·새 대화 여부·가상 재현 문장을 확인한다. 개인정보가 들어간 실제 환자 기록을 요구하지 않는다.
2. 화면 오류인지, 동의 증표 만료인지, 요청 제한인지, 상위 API 오류인지 HTTP 상태와 코드에서 구분한다.
3. health와 실제 배포 버전·현재 소스의 차이를 확인한다. 오류를 재현하지 않고 공급자/사용자 실수로 단정하지 않는다.
4. 최소 범위 수정·검사 후 해당 배포 경로로 반영하고 실제 화면/응답을 확인한다.

긴급 중단이 승인된 경우 Worker 공개 모드를 먼저 끄고 홈페이지 두 노출 스위치를 함께 조정한다. Durable Object나 비밀키를 삭제하지 않는다. 화면만 숨기는 것은 API 중단과 다르다. 복구는 최신 정상 변경을 기준으로 범위를 정하고, 옛 전체 사이트 태그로 무조건 되돌려 후속 칼럼·법률 문서·동의 로직을 없애지 않는다.

## 16. 완료·남은 사항·다음 세션 첫 행동

완료: 일반 공개, 국내/외국인 예약 분류, D 고증 전신 버튼, 반복 말풍선·드래그·접기·패널 모션, 소형 동의 카드, 서버 동의·철회·요청 제한, 일반 증상 과잉 응급 안내 보정, 네 언어 방침 정리 및 실제 사이트 반영.

별도 확인 영역: 공급자 계약·계정 설정에 따라 달라질 수 있는 보관/국외 처리 적용 범위, Console의 현재 잔액·자동 충전·비용, 새로운 실사용 피드백. 이것을 완료했다고 허위 표시하지 않는다. 동시에 과거 검토 메모만으로 공개를 다시 막거나 사용자에게 같은 논쟁을 처음부터 반복하지 않는다.

자동으로 진행하기로 한 신규 기능은 없다. 원본 자산 재생성, 새 모델 변경, 대화 로그 수집, 강제 욕설 횟수 차단, RAG/CMS 연결, 자동 본문 회피, 공급자 문의 발송은 이 인수인계의 승인 범위가 아니다. 필요하면 구체적인 이유와 영향 범위를 제시하고 합의한다.

새 세션은 다음 순서로 시작한다.

```powershell
git fetch origin
git status --short --branch
git log -10 --oneline
```

필수 문서와 이 문서를 읽고 기존 인수인계 이후 바뀐 파일부터 확인한다. 로컬 변경이 없고 뒤처졌을 때만 `git pull --ff-only origin master`한다. 현재 회사 PC의 미추적 `assets/images/dear-favicon.ico`, `다국어-오역-일괄수정.patch`는 사용자 소유로 보존한다. 다른 PC에도 원본 이미지·인증·비공개 파일이 자동 공유된다고 가정하지 않는다.

사용자에게는 현재 확인된 상태와 요청받은 다음 작업을 먼저 설명한다. 인수인계를 읽었다는 이유로 사용자에게 전 과정을 다시 설명하게 하거나, 반대로 모르는 과거 승인을 지어내지 않는다. 후속 작업이 끝나면 이 문서의 영향받는 항목과 `HANDOFF.md`를 함께 갱신해 다음 세션에도 판단 근거가 이어지게 한다.
